# SPEC.md

## 1. 개요
본 프로젝트는 Python Flask와 SQLite를 사용하여 사용자가 할 일을 간단하게 기록하고 관리할 수 있는 최소 기능 제품(MVP) 형태의 Todo 웹 애플리케이션을 구축하는 것을 목표로 한다.

## 2. 기술
- **Language**: Python 3.x
- **Framework**: Flask
- **Database**: SQLite
- **Frontend**: HTML5, Pure CSS3 (외부 프레임워크 미사용)

## 3. 파일 구성
- `app.py`: Flask 애플리케이션 로직 및 라우팅, DB 연동
- `database.db`: SQLite 데이터베이스 파일
- `templates/`: HTML 템플릿 저장 폴더
    - `index.html`: 메인 목록 및 추가 폼
- `static/`: CSS 파일 저장 폴더
    - `style.css`: 애플리케이션 스타일 시트

## 4. 동작 규칙

| 라우트 | 메서드 | 입력 | 결과 |
| :--- | :--- | :--- | :--- |
| `/` | `GET` | 없음 | 모든 할 일 목록 페이지 출력 |
| `/add` | `POST` | `title` (할 일 내용) | 새로운 할 일 추가 후 `/`로 리다이렉트 |
| `/toggle/<int:todo_id>` | `POST` | `todo_id` | 해당 할 일의 완료/미완료 상태 전환 후 `/`로 리다이렉트 |
| `/delete/<int:todo_id>` | `POST` | `todo_id` | 해당 할 일 삭제 후 `/`로 리다이렉트 |

## 5. 화면
- **메인 화면 (`/`)**:
    - 상단: 새로운 할 일을 입력할 수 있는 텍스트 입력창과 추가 버튼
    - 중앙: 할 일 목록 (제목, 완료 여부 상태, 생성 시각 표시)
    - 각 목록 항목 우측: 완료/미완료 토글 버튼, 삭제 버튼

## 6. 테스트

| 요청 | 기대하는 결과 |
| :--- | :--- |
| `GET /` | 할 일 목록 페이지가 정상적으로 렌더링됨 |
| `POST /add` (유효한 제목) | DB에 데이터가 저장되고 목록에 표시됨 |
| `POST /add` (빈 문자열) | 데이터가 저장되지 않거나 오류 없이 무시됨 |
| `POST /add` (공백만 있는 문자열) | 데이터가 저장되지 않거나 오류 없이 무시됨 |
| `POST /add` (매우 긴 문자열) | DB 용량 제한 내에서 정상 저장됨 |
| `POST /toggle/1` (존재하는 ID) | 해당 항목의 `is_completed` 값이 반전됨 |
| `POST /toggle/999` (존재하지 않는 ID) | 에러가 발생하지 않고 메인 페이지로 리다이렉트됨 |
| `POST /delete/1` (존재하는 ID) | 해당 항목이 DB에서 삭제되고 목록에서 사라짐 |
| `POST /delete/999` (존재하지 않는 ID) | 에러가 발생하지 않고 메인 페이지로 리다이렉트됨 |
| `GET /non-existent-route` | 404 Not Found 에러 페이지 반환 |
| `POST /add` (데이터 타입 불일치) | 서버 에러 없이 정상적으로 처리되거나 무시됨 |

## 7. 완료 전 점검
- [ ] 모든 할 일 항목이 생성 시각 순으로 올바르게 정렬되는가?
- [ ] 완료/미완료 토글 버튼 클릭 시 즉각적으로 상태가 반영되는가?
- [ ] 삭제 버튼 클릭 시 항목이 목록에서 즉시 사라지는가?
- [ ] SQLite 데이터베이스 파일이 정상적으로 생성되고 데이터가 영구 저장되는가?
- [ ] CSS가 외부 라이브러리 없이 의도한 대로 적용되었는가?
